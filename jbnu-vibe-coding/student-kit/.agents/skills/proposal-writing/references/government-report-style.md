# 정부 보고서체 작성 기준

공공기관 제출 제안서·사업계획서를 작성할 때 사용한다. 공고가 별도 문체를 요구하면 공고를 우선한다.

## 공식 참고자료

- 국립국어원, 「한눈에 알아보는 공공언어 바로 쓰기(개정판)」: https://korean.go.kr/front/etcData/etcDataView.do?etc_seq=699&mn_id=46&pageIndex=1
- 문화체육관광부·국립국어원, 「쉬운 공공언어 쓰기 길잡이」: https://korean.go.kr/common/download.do?c_file_name=d1ce1113-cc07-4f4c-9ea2-dd920eecba7b.pdf&file_path=etcData
- 행정안전부, 정부혁신 종합계획 문서 예시: https://www.mois.go.kr/plan2024/download/2024post.pdf

## 기본 구조

```text
□ 평가항목 또는 핵심 결론
 ㅇ (핵심어) 핵심 현황·주장·계획
  - 세부 실행내용 또는 객관적 근거
  * 수치 출처·증빙·예외·주의사항
```

계층을 건너뛰지 않는다. `□` 아래에 바로 `*`를 두거나 동일 수준의 bullet 기호를 섞지 않는다.

## 문장 규칙

1. 한 bullet에는 한 메시지만 작성한다.
2. 결론·핵심어·수치를 앞에 둔다.
3. `추진·구축·확대·완료·예정·보유·확보·지원` 등 짧은 명사형으로 마무리한다.
4. 설명이 꼭 필요한 경우에만 `~함`, `~임`, `~예정임`을 사용한다.
5. 공고가 완전한 문장을 요구할 때만 `~합니다`체를 사용한다.
6. `~이다/~한다`가 반복되는 논문식 서술과 긴 줄글을 사용하지 않는다.
7. 명사를 과도하게 나열하지 않고 조사와 동사를 적절히 사용한다.
8. 낯선 외국어·약어는 최초 1회 쉬운 우리말 설명을 붙인다.
9. 수치는 기준일·단위·산식·증빙을 함께 적는다.
10. 실적·현재 상태·계획을 같은 bullet에서 혼합하지 않는다.

## 작성 예시 처리

양식의 `작성 예시`는 삭제 대상 안내문이면서 동시에 답변 범위를 정하는 체크리스트다.

1. 작성 예시의 모든 bullet에 `EX-01`과 같은 번호를 부여한다.
2. 각 bullet을 독립된 `□` 또는 `ㅇ` 소항목으로 변환한다.
3. 해당사항이 없으면 삭제하지 말고 `해당 없음`과 그 이유를 적는다.
4. 교육용 자료에 없는 항목은 추측하지 않고 원본 양식의 빈칸으로 유지한다.
5. 최종 이식 직전에 `작성 예시 → 답변 위치 → 근거 → 증빙` 대응표의 누락이 0건인지 확인한다.
6. 대응 완료 후 원본의 파란색 안내문과 작성 예시 문구만 삭제한다.

## 좋은 예

```text
□ 기업 개요 및 주요 연혁
 ㅇ (기업 개요) 2026년 3월 경기도 화성시에 AI 소프트웨어 법인 설립
  - 핵심 제품: 로컬 우선 비주얼 AI 에이전트 Naia
 ㅇ (주요 연혁) 제품 공개·기술자산·사업화 기반을 순차 확보
  - 2026.3. Naia OS 공개(3개 운영체제·14개 언어)
  - 2026.3.~5. AI 관련 특허 12건 출원
  * 근거: 법인등기부, 제품 배포자료, 특허 출원서
```

## 피해야 할 예

```text
넥스테인은 2026년 3월 설립된 AI 회사이다. 다양한 경험을 가진 인력이 여러 사업을 수행하고 있으며 앞으로 글로벌 시장에도 진출하고자 한다.
```

문제점: 작성 예시 소항목 구분 없음, 수치·증빙 부족, 현재와 계획 혼합, 긴 줄글.

## 최종 점검

- [ ] 작성 예시의 모든 bullet에 독립 답변이 있음
- [ ] `□ → ㅇ → - → *` 계층이 일관됨
- [ ] 한 bullet에 한 메시지만 있음
- [ ] 명사형 또는 허용된 종결어미가 일관됨
- [ ] 수치에 기준일·단위·증빙이 있음
- [ ] 실적과 계획이 분리됨
- [ ] 긴 줄글과 반복되는 `~이다/~한다`가 없음
- [ ] 어려운 외국어·약어에 설명이 있음
